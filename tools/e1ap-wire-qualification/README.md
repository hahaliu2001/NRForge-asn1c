# E1-P4 finite independent complete-PDU qualification

Requires pinned pycrate0.7.11. The oracle is freshly compiled from exactly the
six frozen E1AP modules; it does not use an installed alternate schema.
Build the E1-P3 generated complete library and run its actual linked all-slot
integration receipt first. The qualifier refuses changed archive/attested inputs.

```sh
python3 tools/e1ap-wire-qualification/qualify.py \
  --asn1-root /path/NRForge-RAN/src --generated-root /path/generated-e1ap \
  --archive /path/build/libnrforge_e1ap.a \
  --archive-receipt /path/dispatch-integration-e1-p3.json \
  --work /new/e1ap-wire-campaign --output /tmp/e1ap-wire-candidate.json \
  --jobs 3 --cxx /usr/bin/g++
```

Full72 identity closure uses native/frozen/generated evidence and actual registry
declarations. Public-only C++20 TUs construct expected BODY values from native
semantics, assert every selected decoded field, compare complete native/generated
bytes and native-backdecode actual generated bytes. No byte normalization or
same-codec roundtrip oracle is used. All values include declared mandatory/minimum
rows, low/contrast values, additional top-level IE rows and received criticalities.
All six selected unsigned64 UL/DL paths exercise nine boundaries through UINT64_MAX.
Native private empty-set/unknown-extension warnings remain in logs; these cases
are explicitly labelled opaque transparency, with no known vendor/addition claim.

Each identity's baseline tests physical mutations, malformed-known refusal, exact
and insufficient budgets and owned copy/move after input damage. Exhaustive
unknown/absent root slot receive-only policy is separate from known sender byte
agreement; selected unknown outer additions also remain receive-only. Strict
object/executable validation and full input inventories are checked before/after.
A failed rerun removes stale candidate output.

The runner emits a MATCHED candidate. Only after independent review, run
`promote.py --candidate ... --review review.md --output-dir ...` to create a
lossless gzip/base64 accepted-profile envelope and compact qualification summary.
The review must contain `**ACCEPT**` and exactly one standalone
`Candidate-SHA256: <sha256 of the original candidate bytes>` line; an unrelated
or mismatched review is rejected before any accepted output is written.
The decompressed payload must match the exact reviewed original JSON bytes:

```python
import base64, gzip, hashlib, json
from pathlib import Path
e = json.loads(Path('tools/e1ap-wire-qualification/accepted-profile.json').read_text())
raw = gzip.decompress(base64.b64decode(e['data'], validate=True))
assert len(raw) == e['profile_bytes']
assert hashlib.sha256(raw).hexdigest() == e['profile_sha256']
Path('/tmp/e1ap-accepted-profile.json').write_bytes(raw)
```

Pass that expanded original to `--accepted-profile` for replay; never pass the
storage envelope itself. Logical and storage hashes are distinct. Every full
vector, semantic hash, selected path/value trace and omission remains retained.

Acceptance is finite. Unreached typed sizes/fragmentation, nested combinations,
future typed additions, vendor/contained payload interpretation, application
mandatory-IE/conditional/state policy and live interoperability remain outside
scope. E1-P5/E1-P6 deliver SDKs. No benchmark or frozen-schema changes.
