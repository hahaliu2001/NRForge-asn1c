output and stable inputs. The candidate status deliberately remains
`MATCHED_F1AP_CANDIDATE_REQUIRES_INDEPENDENT_REVIEW`; the external
`qualification-summary.json` and `review.md` record approval of its exact hash.
The accepted logical payload is an exact copy, not an edited or normalized
candidate. The committed file is a checked lossless gzip/base64 envelope because
the GitHub connection's 16 MiB request limit rejects the original pretty-printed
JSON once escaped. Restore and verify the original SHA/size using the README
before passing it to `--accepted-profile`. The external summary distinguishes
the envelope's storage hash from the approved logical profile hash; independent
review also verifies exact decompression. No qualification source changed.

live-vendor interoperability. Unreached sizes, combinations, nesting, extension
selections, nested optional fields, application conditions/state/mandatory-IE
policy, contained RRC/NAS interpretation and vendor payload semantics remain
unqualified. F1AP's fourth non-extensible root is rejected immediately at bit 2;
the negative policy check is not qualification of fourth-root payload semantics.
