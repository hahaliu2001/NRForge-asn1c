## Delivered interface

The installed tree contains public typed messages/types, runtime/status APIs,
BODY/PDU wrappers and `sdk_version.hpp`, the complete `libnrforge_f1ap.a`,
relocatable CMake exports and protocol-specific provenance. Private generated
codec/mapping headers are excluded. CMake optionally checks
`NRFORGE_F1AP_EXPECTED_FINGERPRINT`; every public entry point requires the exact
header/library identity symbol even in a no-op consumer. Identity fingerprints
check consistency, not authenticity or cross-toolchain ABI.

Protocol-qualified public includes permit NGAP and F1AP in one translation unit
and one prefix, in either include/link order. Existing NGAP package/target names
remain available. Applications should use qualified installed includes when
combining protocols.

## Toolchain and recovery

Local qualification uses GNU/Linux, g++ 13.3.0, strict C++20/O0 compilation,
CMake 4.4.4, GNU gold for SDK build/link gates, and lld 18.1.3 for the final
installed consumers. Consumer executables alone use `-Wl,-s`; installed archives
remain intact. The consumer linker is selectable with `--linker`.

The initial F1AP parallel build was terminated by compiler resource pressure;
serial compilation completed the same generated sources. The first NGAP build
had two invalid object outputs; their targeted recompilation repaired the archive
and the real full registry gate then passed. Initial dual-protocol gold linking
was killed; lld completed the same two complete archives. Failed attempts are
not counted as successful acceptance. The final evidence reconciles actual
archive/ELF/symbol closure and successful executions rather than inferring success
from compiler exit status. Isolation restores inputs on failure and refuses to
overwrite recreated content or symlinks.

The focused GitHub workflow builds both SDKs and repeats native fixture,
relocated consumer and seal checks. It requires the read-only private-schema
secret `NRFORGE_SCHEMA_READ_TOKEN`; no remote CI PASS is claimed here.
