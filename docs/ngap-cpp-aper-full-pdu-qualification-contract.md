# Full NGAP-PDU interoperability qualification contract

Selected by the Owner on 2026-10-10. Baseline: `3312ff011b24fe72e5297fd5129495ac32caac7e`.

## Target and independent reference

The finite acceptance campaign covers every frozen message identity: 81 initiating,
32 successful and 18 unsuccessful outcomes, for 81 procedures. Each case must
exercise a complete typed PDU rather than BODY-only bytes or an opaque fallback.
The unchanged six-module TS 38.413 V18.10.0 source identity guard is mandatory
before both Parser/Fixer extraction and independent pycrate 0.7.11 compilation.
Installed alternative NGAP releases and synthetic replacement schemas cannot
establish native full-message agreement.

Reference values must include actual IE contents. The baseline profile uses
mandatory object-set rows and legal minimal nested values; additional cases
exercise declared optional/conditional rows without claiming their application
condition is satisfied. A wire-valid conditional or empty list is not evidence
of procedure/application mandatory-presence conformance. Private empty object
sets have separately identified vendor-opaque cases rather than fabricated
known typed rows. Received criticality is independently varied; it does not
change known target dispatch.

## Required relations

Generate all six headers from owned metadata after deleting Parser/Fixer trees,
repeat generation and compare exact outputs. Strictly compile and execute the
real generated codec. Construct expected typed values independently from native
semantic values, encode them and compare complete byte strings including length;
native-decode generated bytes and compare semantics. Decode native complete PDUs
and compare every selected field, presence, list count/order, CHOICE wrapper,
ENUMERATED value, integer, bit length/value, byte/string payload, IOC identifier,
received criticality and typed payload. A generated decode/reencode roundtrip
alone is insufficient. Malformed known payloads cannot silently become opaque.

Expected physical envelope framing and malformed inputs are independently
derived. Cover roles, criticalities, byte-prefix truncation, alignment, trailing
data and exact/insufficient resource limits. Preserve unknown-envelope and
unknown-IE behavior under existing policy, with receive-only refusal recorded
separately from typed sender agreement. Retain historical N11 evidence and
replay its accepted compatibility gate when outcome support changes.

## Publication and limitations

Record exact source/tool/header fingerprints, case identities, value coverage,
complete-byte and semantic outcomes, reference exceptions and unresolved
disagreements. Independently review tooling, expectations and production fixes
before accepting/publishing the resulting finite profile. Never auto-classify
a mismatch as a reference bug or normalize bytes to obtain agreement. Any
reference-only limitation needs a separate, explicit proof and outcome label.

Passing all identities establishes interoperability with the pinned independent
implementation for the recorded acceptance profile, not exhaustive value-space
coverage, live vendor interoperation, application state-machine behavior,
RRC/NAS/contained-payload correctness or an unrestricted PER implementation.
Frozen constraints, runtime ceilings and unsupported extension/vendor semantics
remain visible. No performance benchmark is part of this milestone.
